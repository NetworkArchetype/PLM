6.1 Overview

The PLM validation suite includes benchmark demonstrations across three distinct computational domains. These benchmarks serve not as claims of novel algorithmic advantage, but as concrete evidence that the PLM framework integrates with real computational workloads and that the surrounding infrastructure—from GPU acceleration to quantum circuit simulation—is functional and produces verifiable results.

The three domains covered by the benchmark suite are:

  1. NP-hard combinatorial problems — 3-SAT, Traveling Salesman Problem (TSP), and the 0/1 Knapsack Problem. These are canonical problems from computational complexity theory, each known to be NP-hard (or NP-complete). We solve real instances of non-trivial size using standard algorithms.
  2. Cryptographic operations — RSA-2048 key generation, digital signature (PSS padding, SHA-256), and public-key encryption (OAEP padding, SHA-256). These demonstrate that the PLM framework integrates with industrial-strength cryptographic libraries.
  3. Quantum algorithm demonstrations — Grover's search algorithm applied to a 3-SAT instance, implemented as a parametric quantum circuit in Google Cirq. This demonstrates that the quantum circuit infrastructure is functional and can encode combinatorial search oracles.
Remark 6.1 (Scope of Claims)

The benchmarks in this chapter demonstrate integration and functionality. The PLM framework does not claim to solve NP-hard problems in polynomial time, nor does it claim to be a cryptographic primitive. Each benchmark is accompanied by honest assessment of what it does and does not demonstrate.

6.2 3-SAT Solver

6.2.1 Problem Definition

The Boolean Satisfiability Problem (SAT) asks whether there exists an assignment of truth values to Boolean variables such that a given propositional formula evaluates to true. In the 3-SAT variant, the formula is in conjunctive normal form (CNF) with exactly 3 literals per clause:

\[ \varphi \;=\; \bigwedge_{i=1}^{m} \bigl( l_{i,1} \lor l_{i,2} \lor l_{i,3} \bigr) \]

where each literal \(l_{i,j}\) is either a variable \(x_k\) or its negation \(\neg x_k\). 3-SAT is the canonical NP-complete problem: it was the first problem shown to be NP-complete (Cook–Levin theorem, 1971), and all problems in NP can be reduced to it in polynomial time.

6.2.2 Toy Instance (3 Variables)

To illustrate the solution space structure, we first examine a toy instance with \(n = 3\) variables and a small number of clauses. The brute-force solver enumerates all \(2^n = 2^3 = 8\) possible assignments and tests each against every clause.

6.2.3 Full Benchmark Instance (\(n = 22\))

The full benchmark instance tests the solver at a scale where brute-force enumeration is non-trivial. The instance parameters are chosen to sit near the well-known phase transition threshold for random 3-SAT.

Definition 6.1 (3-SAT Phase Transition)

For random 3-SAT instances with \(n\) variables and \(m\) clauses, the clause-to-variable ratio \(\alpha = m/n\) exhibits a sharp phase transition near \(\alpha_c \approx 4.27\). Below this threshold, almost all instances are satisfiable; above it, almost all are unsatisfiable. Instances near the threshold are the hardest on average.

Our benchmark instance has \(n = 22\) variables and \(m = 88\) clauses, giving a clause-to-variable ratio of:

\[ \alpha \;=\; \frac{m}{n} \;=\; \frac{88}{22} \;=\; 4.0 \]

This is slightly below the phase transition threshold of \(\alpha_c \approx 4.27\), placing the instance in the “satisfiable but hard” regime.

6.3 Traveling Salesman Problem (TSP)

6.3.1 Problem Definition

The Traveling Salesman Problem (TSP) is one of the most studied problems in combinatorial optimisation. Given a set of \(n\) cities and the distances between each pair of cities, the objective is to find the shortest possible route that visits each city exactly once and returns to the starting city.

\[ \min_{\sigma \in S_n} \sum_{i=1}^{n} d\bigl(\sigma(i),\, \sigma(i+1 \bmod n)\bigr) \]

where \(S_n\) denotes the set of all permutations of \(n\) cities and \(d(\cdot, \cdot)\) is the distance metric. The number of distinct tours is \((n-1)!/2\) for the symmetric case, which grows super-exponentially. For \(n = 200\), this number is astronomically large—far beyond any possibility of exhaustive enumeration.

6.3.2 Method and Results

The PLM benchmark suite employs a nearest-neighbor heuristic with GPU acceleration via CuPy/CUDA when available. The nearest-neighbor heuristic is a greedy algorithm that, at each step, moves to the closest unvisited city. While this does not guarantee an optimal tour, it produces a feasible solution in \(O(n^2)\) time and serves as a practical baseline.

In Plain Language

Imagine a delivery driver who must visit 200 addresses. Finding the absolute shortest route is one of mathematics' hardest problems—the number of possible routes is larger than the number of atoms in the universe. The PLM benchmark suite solves real instances of this problem using a combination of clever heuristics and GPU acceleration, demonstrating that the framework integrates with serious computational workloads.

The number of possible tours for \(n = 200\) cities is:

\[ \frac{(n-1)!}{2} \;=\; \frac{199!}{2} \;\approx\; 10^{374} \]

This number dwarfs the estimated number of atoms in the observable universe (\(\approx 10^{80}\)), making exhaustive search impossible. The nearest-neighbor heuristic provides a polynomial-time approximation that produces a feasible tour in \(O(n^2)\) time.

6.4 0/1 Knapsack Problem

6.4.1 Problem Definition

The 0/1 Knapsack Problem asks: given a set of \(n\) items, each with a weight \(w_i\) and a value \(v_i\), and a knapsack with capacity \(W\), select a subset of items that maximises total value without exceeding the weight capacity:

\[ \max \sum_{i=1}^{n} v_i \cdot x_i \qquad \text{subject to} \qquad \sum_{i=1}^{n} w_i \cdot x_i \;\leq\; W, \qquad x_i \in \{0, 1\} \]

Although the decision version of the knapsack problem is NP-complete, exact solutions can be computed via dynamic programming in pseudo-polynomial time \(O(nW)\). This is feasible when the capacity \(W\) is not excessively large.

6.5 RSA-2048 Cryptographic Demonstration

6.5.1 Purpose

The RSA-2048 benchmark demonstrates that the PLM framework integrates with industrial-strength cryptographic libraries. This is not a claim that PLM itself is a cryptographic primitive or key derivation function. The benchmark exercises three fundamental RSA operations:

  1. Key generation — Generation of a 2048-bit RSA keypair with public exponent \(e = 65537\).
  2. Digital signature — Signing a message using PSS (Probabilistic Signature Scheme) padding with SHA-256 as the hash function, followed by verification of the signature.
  3. Encryption and decryption — Encrypting a plaintext message using OAEP (Optimal Asymmetric Encryption Padding) with SHA-256, followed by decryption and verification that the recovered plaintext matches the original.

6.5.2 Technical Details

RSA security rests on the computational hardness of factoring the product of two large primes. For a 2048-bit modulus \(N = pq\):

\[ N \;=\; p \cdot q, \qquad |N| = 2048 \text{ bits}, \qquad e = 65537 = 2^{16} + 1 \]

The public exponent \(e = 65537\) is the standard choice, being a Fermat prime that allows efficient modular exponentiation. The private key \(d\) is computed as the modular inverse of \(e\) modulo \(\phi(N) = (p-1)(q-1)\):

\[ d \;\equiv\; e^{-1} \pmod{\phi(N)} \]

6.6 Grover's Algorithm on 3-SAT (Quantum Demo)

6.6.1 Background

Grover's algorithm (1996) provides a quadratic speedup for unstructured search problems. Given a search space of size \(N\) with \(M\) marked (satisfying) elements, Grover's algorithm finds a marked element with high probability in \(O(\sqrt{N/M})\) oracle queries, compared to \(O(N/M)\) for classical random search.

The algorithm operates by repeatedly applying two operations:

  1. Oracle \(U_f\): marks the satisfying assignments by flipping their phase.
  2. Diffusion operator \(D\): amplifies the amplitude of marked states (amplitude amplification).

The optimal number of Grover iterations is:

\[ k_{\text{opt}} \;=\; \left\lfloor \frac{\pi}{4} \sqrt{\frac{N}{M}} \right\rfloor \]

6.6.4 Honest Assessment

Remark 6.4 (Honest Assessment of Grover Demo)

The following points provide a candid evaluation of what this quantum demonstration does and does not show:

  1. No Grover speedup is claimed. With 0 Grover iterations, the circuit performs no amplitude amplification. The initial Hadamard gates create a uniform superposition, and measurement simply samples from this uniform distribution. This is essentially random sampling.
  2. The 64% satisfying rate is consistent with randomness. The theoretical expectation under uniform sampling is \(M/N = 6/8 = 75\%\). With only 50 shots, the standard deviation is: \[ \sigma \;=\; \sqrt{n \cdot p \cdot (1-p)} \;=\; \sqrt{50 \cdot 0.75 \cdot 0.25} \;\approx\; 3.06 \] The observed 32 satisfying measurements (64%) is \((37.5 - 32) / 3.06 \approx 1.8\) standard deviations below expectation—unusual but not statistically significant at conventional thresholds.
  3. The “101” anomaly is a statistical fluctuation. Assignment 101 (a non-satisfying assignment) appeared 13 times out of 50 shots, making it the most frequently measured outcome. Under uniform sampling, each assignment has expected count \(50/8 = 6.25\), and seeing 13 for any particular assignment is a fluctuation of \((13 - 6.25) / \sqrt{6.25 \cdot 7/8} \approx 2.9\) standard deviations—notable but expected when examining 8 simultaneous outcomes (multiple testing).
  4. Optimal iterations analysis. The optimal number of Grover iterations for this problem would be: \[ k_{\text{opt}} \;=\; \left\lfloor \frac{\pi}{4} \sqrt{\frac{N}{M}} \right\rfloor \;=\; \left\lfloor \frac{\pi}{4} \sqrt{\frac{8}{6}} \right\rfloor \;=\; \left\lfloor 0.907 \right\rfloor \;=\; 0 \] Since the optimal number of iterations rounds down to 0 (or could be 1, depending on convention), this particular instance is poorly suited to demonstrating Grover speedup. The high satisfying fraction (\(M/N = 75\%\)) means that even random sampling finds satisfying assignments most of the time.
  5. This is a demonstrator, not a speedup proof. The purpose of this benchmark is to verify that the quantum circuit infrastructure (oracle construction, Hadamard initialisation, measurement, Cirq simulation) is functional and produces physically meaningful output. It is not a claim of quantum computational advantage.

Despite these caveats, the Grover demonstration successfully validates the end-to-end quantum circuit pipeline: CNF formula encoding into an oracle, Hadamard initialisation, Grover iteration (even at 0 rounds), measurement, and statistical analysis of results. This infrastructure is the foundation upon which more sophisticated quantum algorithms could be built.

6.8 What the Benchmarks Prove

The benchmark suite provides concrete evidence for the capabilities and limitations of the PLM framework. We summarise these in two categories: what the benchmarks do prove, and what they do not prove.

Evidence 6.8 — What the Benchmarks Prove

Demonstrated capabilities:

  1. Real computational integration. The PLM framework integrates with real computational workloads, including NP-hard combinatorial solvers, cryptographic libraries, and quantum circuit simulators.
  2. Functional validation harness. The validation harness can solve actual NP-hard instances of non-trivial size: \(2^{22}\) search space for 3-SAT, 200 cities for TSP, and 300 items for Knapsack.
  3. Quantum circuit infrastructure. The quantum circuit infrastructure is functional and produces meaningful output. The Cirq-based pipeline can encode combinatorial problems as quantum oracles and execute measurement protocols.
  4. GPU acceleration. The system correctly detects and utilises GPU acceleration (CuPy/CUDA) when available, demonstrating hardware adaptability.
  5. Cryptographic library integration. Industrial-strength cryptographic operations (RSA-2048 key generation, signing, verification, encryption, decryption) work correctly within the framework.

Explicit non-claims:

  1. PLM does not solve NP-hard problems in polynomial time. The 3-SAT solver uses brute-force enumeration; the TSP solver uses a polynomial-time heuristic (not an exact algorithm); the Knapsack solver uses pseudo-polynomial dynamic programming. None of these constitute polynomial-time exact algorithms for NP-hard problems.
  2. PLM is not a cryptographic key derivation function. The RSA-2048 benchmark demonstrates integration with the Python cryptography library. PLM itself is not a cryptographic primitive and makes no security guarantees.
  3. The Grover demo is a demonstrator, not a quantum speedup proof. With 0 Grover iterations, the circuit performs uniform sampling. The purpose is to validate the quantum circuit infrastructure, not to claim quantum computational advantage.
